# Finetune SmolVLA locally for an AgileX Piper arm

This tutorial shows how to train a **SmolVLA** policy for an **AgileX Piper** using a **local GPU** and a dataset you already recorded with `phosphobot`.

The goal here is the simplest local workflow:

- train on **your own machine**
- use a **local dataset path**
- do **not** depend on the phosphobot hosted "AI & Training" page

## Should I use Miniconda?

No. **Miniconda is optional**, not required.

For this tutorial, the recommended setup is:

- Python `3.10`
- a normal virtual environment created with `uv`

Use Miniconda only if:

- you already use it for your ML environments
- you prefer `conda activate ...`
- your GPU/PyTorch setup is already working well there

If you have no strong preference, use `uv`. It is simpler for this repo.

## What this tutorial assumes

- You recorded a **Piper** dataset in **LeRobot format** using phosphobot.
- Your dataset lives locally, for example:

```bash
dataset/pickup_bottle
```

- You have an NVIDIA GPU and recent CUDA drivers.
- You are on Linux. Piper support in this repo is Linux-first.

## Important Piper note

You do **not** need a Piper-specific training architecture.

The dataset generated by phosphobot already contains the right Piper action/state dimensions. In this repo, Piper is represented with 7 servo ids, so the saved dataset metadata matches the robot automatically.

## 1. Clone the repository

```bash
git clone https://github.com/phospho-app/phosphobot.git
cd phosphobot
```

## 2. Create a local Python environment

### Recommended: `uv`

```bash
uv venv --python 3.10 smolvla-piper
source smolvla-piper/bin/activate
```

Install phosphobot and SmolVLA training dependencies:

```bash
uv pip install -e ./phosphobot
uv pip install "lerobot[smolvla]==0.3.3"
```

### Optional: Miniconda

If you prefer Miniconda, use:

```bash
conda create -n smolvla-piper python=3.10 -y
conda activate smolvla-piper
pip install -e ./phosphobot
pip install "lerobot[smolvla]==0.3.3"
```

## 3. Check that your dataset looks correct

Set your dataset path to the **full dataset directory** (including the dataset name):

```bash
export DATASET_ROOT=./dataset/pickup_bottle
```

> **Important:** `DATASET_ROOT` must point to the dataset folder itself, not its parent.
> lerobot looks for `$DATASET_ROOT/meta/info.json` directly.

Make sure the expected folders exist:

```bash
ls "$DATASET_ROOT"
ls "$DATASET_ROOT/meta"
ls "$DATASET_ROOT/data/chunk-000" | head
```

You should see at least:

- `meta/`
- `data/`
- `videos/`

This training path works best with the LeRobot-style dataset generated by phosphobot.

## 4. Choose a starting batch size

Start conservatively. SmolVLA can use a lot of VRAM.

Practical starting points:

- `batch_size=8` for 8-12 GB VRAM
- `batch_size=16` for 16-24 GB VRAM
- `batch_size=32` for 24-48 GB VRAM
- `batch_size=64` for large GPUs

If training crashes with CUDA OOM, lower the batch size first.

## 5. Run SmolVLA training locally

### Log in to Weights & Biases

Training uses W&B for logging (`--wandb.enable=true`). Log in before starting:

```bash
wandb login
```

You will be prompted to paste your API key from [wandb.ai/authorize](https://wandb.ai/authorize). This only needs to be done once per machine.

### Start training

This is the recommended command for **fine-tuning the pretrained SmolVLA base model** on your Piper dataset:

```bash
lerobot-train \
  --policy.path=lerobot/smolvla_base \
  --policy.push_to_hub=false \
  --dataset.repo_id=pickup_bottle \
  --dataset.root="$DATASET_ROOT" \
  --batch_size=16 \
  --steps=20000 \
  --output_dir=outputs/train/piper_smolvla \
  --job_name=piper_smolvla \
  --policy.device=cuda \
  --wandb.enable=true
```

> `$DATASET_ROOT` must be the full path to the dataset folder (e.g. `./dataset/pickup_bottle`), **not** the parent directory. See step 3.

Once training starts, W&B will print a run URL in the logs (e.g. `wandb: 🚀 View run at https://wandb.ai/<your-entity>/...`). Open that URL in your browser to monitor loss curves and training metrics in real time.

### What these arguments mean

- `--policy.path=lerobot/smolvla_base`
  loads the public pretrained SmolVLA base model and fine-tunes it
- `--policy.push_to_hub=false`
  keeps the run fully local and avoids requiring `--policy.repo_id`
- `--dataset.repo_id=pickup_bottle`
  the name of the dataset (used for metadata and logging)
- `--dataset.root="$DATASET_ROOT"`
  full path to the dataset directory — must contain `meta/info.json`
- `--batch_size=16`
  safe starting value for many single-GPU machines
- `--steps=20000`
  reasonable first fine-tune budget
- `--output_dir=outputs/train/piper_smolvla`
  writes checkpoints and artifacts locally
- `--policy.device=cuda`
  uses your GPU
- `--wandb.enable=true`
  enables logging to Weights & Biases for tracking training progress

## 6. Monitor training

In another terminal:

```bash
watch -n 2 nvidia-smi
```

If you see an out-of-memory error:

1. stop the run
2. reduce `--batch_size`
3. restart training

Example with a smaller batch size:

```bash
lerobot-train \
  --policy.path=lerobot/smolvla_base \
  --policy.push_to_hub=false \
  --dataset.repo_id=pickup_bottle \
  --dataset.root="$DATASET_ROOT" \
  --batch_size=8 \
  --steps=20000 \
  --output_dir=outputs/train/piper_smolvla_bs8 \
  --job_name=piper_smolvla_bs8 \
  --policy.device=cuda \
  --wandb.enable=true
```

Where `$DATASET_ROOT=./dataset/pickup_bottle` (see step 3).

## 7. Where the trained model ends up

Your trained checkpoints and config files will be under:

```bash
outputs/train/piper_smolvla
```

That directory is local. Nothing is uploaded automatically by this command.

## 8. Do I need a Hugging Face account for this local flow?

Usually, **no**, if:

- your dataset is local
- you are not pushing the trained model to the Hub
- the pretrained base model stays publicly downloadable in your environment

For `lerobot==0.3.3`, make that explicit in the command with:

```bash
--policy.push_to_hub=false
```

You only need a Hugging Face account if you want to:

- push the model to the Hub
- pull a private dataset
- use private model storage

## 9. Do I need the phosphobot sidebar for this?

No.

This tutorial is a **terminal-only local training flow**. It does not use the dashboard's hosted training service.

## 10. Troubleshooting

### `lerobot-train: command not found`

Your environment is probably not activated.

If you used `uv`:

```bash
source smolvla-piper/bin/activate
```

If you used conda:

```bash
conda activate smolvla-piper
```

### CUDA OOM

Reduce the batch size:

- from `16` to `8`
- then `4` if needed

### Dataset errors

Check that your dataset really is a LeRobot dataset and that `meta/`, `data/`, and `videos/` exist under the same root.

### Training is very slow

This is normal on smaller GPUs. Start with:

- lower batch size
- fewer steps for your first test run, for example `--steps=2000`

## 11. A minimal smoke test

Before a full run, do a short test:

```bash
export DATASET_ROOT=./dataset/pickup_bottle

lerobot-train \
  --policy.path=lerobot/smolvla_base \
  --policy.push_to_hub=false \
  --dataset.repo_id=pickup_bottle \
  --dataset.root="$DATASET_ROOT" \
  --batch_size=4 \
  --steps=200 \
  --output_dir=outputs/train/piper_smolvla_smoke \
  --job_name=piper_smolvla_smoke \
  --policy.device=cuda \
  --wandb.enable=true
```

If that works, rerun with your real batch size and step count.
